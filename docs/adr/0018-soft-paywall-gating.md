# ADR-0018: Soft Paywall Gating and Per-Wall Conversion Tracking

## Status
Accepted

## Context
Handbook §18.3 names five specific walls — the paywall may only appear on the 4th+ watchlist item, archive depth beyond 30 days, real-time alerts, full reporter history, and export — and requires that "every wall states plainly what's behind it and what it costs" and that conversion is "measured per wall separately" (§18.5). Before this ADR, none of the five were real: `WatchButton` was a `useState` toggle with no persistence and no limit; claim history was cut at a hardcoded 4-item count, not 30 days; the reliability reporter index showed every reporter unbounded; "Export CSV" and "Export ledger" were static links to `/pro` with no backend behind them; and `GET /billing/entitlements/{email}` (built in the prior Stripe-billing phase, ADR-0017) was never called from the frontend at all — there was no client-side notion of "who is this visitor" to check it against.

## Decision
1. **A minimal, explicit identity primitive** (`apps/web/lib/identity.ts`): an email stored in `localStorage`, surfaced in the masthead as "Identify yourself" (`apps/web/components/account-status.tsx`). This is deliberately *not* a login — there is no verification the visitor owns the email — consistent with the scope boundary already drawn in ADR-0017. Checkout and the billing portal now also write this identity on success, so a visitor is recognised immediately after subscribing rather than needing a separate step.
2. **`useEntitlements()`** (`apps/web/lib/entitlements.ts`): the one hook every gate reads, wired to the real persisted entitlements endpoint. Fails safe to the free tier on any error — never fails open into Pro.
3. **A real, but deliberately client-only, watchlist** (`apps/web/lib/watchlist.ts`): persisted to `localStorage`, not a server-side model. This is a scope decision, not an oversight: gating the "4th item" requires a real count, but a full cross-device watchlist service (DB model, CRUD API, sync) is a separate, larger product surface than "make the paywall real." Free users get a fully working watchlist on the device they're using; it does not follow them to another device.
4. **Archive depth and reporter history, both now genuinely 30-day-windowed** (`FREE_ARCHIVE_WINDOW_DAYS = 30`, mirrored between `packages/database/billing_repository.py` and `apps/web/lib/entitlements.ts`): `claim-timeline.tsx` (event page) and the new `subject-claim-history.tsx` (reporter/outlet profile) both filter by claim age instead of a fixed count, matching the handbook's stated rule instead of an arbitrary cutoff.
5. **Reporter index capped at 20 for Free** (`FREE_REPORTER_INDEX_LIMIT = 20`, `apps/web/components/reporters-table.tsx`), matching the handbook's pricing table ("Reporter-level reliability: Top 20 only" free / "all tracked reporters" Pro) — previously unbounded for everyone.
6. **A real export endpoint** (`GET /api/v1/claims/export`, `apps/api/app/routers/claims.py`): checks the caller's persisted entitlement by email server-side before returning anything, streams CSV or JSON, scoped to an event or a reporter/outlet. `apps/web/components/export-button.tsx` triggers a real download for Pro and a tracked wall for Free, replacing the unconditional link to `/pro`.
7. **Per-wall conversion tracking, not just UI copy**: `PaywallEventModel` (`packages/database/models.py`), `POST /billing/paywall-events`, and `GET /admin/paywall-conversion` (shown/clicked/conversion-rate per `wall_id`). Every wall (`PaywallWall`, `apps/web/components/paywall-wall.tsx`) fires a "shown" event on mount and a "clicked" event on its CTA — the handbook's "measure the conversion rate of each wall separately" is now a real, queryable number, not an assumption.
8. **"Real-time alerts" is explicitly not gated in this ADR.** No alerts feature — digest or real-time — exists anywhere in the codebase to gate; a standalone weekly newsletter script (`scripts/generate_newsletter.py`) is unrelated to per-user delivery. Building a fake toggle that unlocks nothing would be worse than not building it. Four of the five named walls are real; this one remains a pricing-page comparison line only, until an actual alerts/notification feature exists.

## Consequences
- **Positive**: verified live against a running API and web server with seeded data spanning the 30-day boundary (one claim 45 days old, one fresh) — the export endpoint correctly returns 403 for a free email and a real CSV/JSON for a Pro one; the admin conversion endpoint correctly aggregates shown/clicked counts per wall; all three affected pages (event, reliability index, reliability subject) render with the real data with no server errors. 10 new backend tests (`tests/unit/test_paywall_gating.py`).
- **Negative / follow-ups, stated explicitly**:
  - **Client-only gating has a visible seam**: because identity lives in `localStorage` with no server-side cookie/session, every gated component defaults to *showing everything* during server-side render and the brief pre-hydration window (the component doesn't yet know if the visitor is Free or Pro), then narrows to the free-tier view once the client-side entitlement check resolves. This is consistent with the "soft, contextual" design the handbook asks for — it was never meant to be a hard security boundary, and the same data is one API call away regardless — but it means a fast anonymous visitor could, in principle, glimpse content a split second before the wall applies. Closing this properly needs server-side identity (a cookie/session), which is the same passwordless-auth gap already logged in ADR-0017.
  - **No UI was built for the admin paywall-conversion endpoint** — it's real and queryable (`GET /admin/paywall-conversion`) but there's no `/admin/paywall` page rendering it yet, unlike the existing cost-telemetry admin page. Follow-up, not done here.
  - **Watchlist has no cross-device sync**, by design (see point 3) — flagged so it isn't mistaken for a bug later.
  - **Real-time alerts remains ungated** because it doesn't exist (see point 8) — this is the one of the handbook's five named walls not addressed by this ADR.
